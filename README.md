SISTEMA DE CITAS MÉDICAS

1. Descripción del proyecto

El Sistema de Citas Médicas es una propuesta académica que busca facilitar la organización y administración de los servicios de salud. Su finalidad es mantener organizada la información de los pacientes, médicos y citas, permitiendo consultar horarios y gestionar las solicitudes de atención médica.

Este proyecto se desarrolla como una actividad del módulo de Calidad del Software (SQA), utilizando GitHub para documentar el trabajo en equipo y llevar un control de las modificaciones realizadas.

2. Objetivo general

Proponer un sistema que facilite la gestión de citas médicas, permitiendo organizar los registros de pacientes, consultar médicos disponibles y administrar las citas de manera sencilla y ordenada.

3. Funcionalidades principales

1. Registrar pacientes.
2. Consultar médicos disponibles.
3. Programar citas médicas.
4. Modificar citas existentes.
5. Cancelar citas.
6. Consultar el historial de citas.
7. Consultar horarios disponibles.

4. Usuarios del sistema

Administrador: encargado de gestionar los registros y supervisar el funcionamiento del sistema.

Médico: puede consultar sus horarios y las citas que tiene programadas.

Paciente: puede solicitar, consultar, modificar y cancelar sus citas médicas.

5. Requisitos del sistema

Requisitos funcionales

1. Permitir el registro de pacientes.
2. Mostrar los médicos disponibles.
3. Permitir programar citas.
4. Permitir modificar citas.
5. Permitir cancelar citas.
6. Consultar el historial de citas.
7. Mostrar los horarios disponibles.

Requisitos no funcionales

1. Proteger los datos personales de los pacientes.
2. Mantener la información organizada.
3. Ofrecer facilidad de uso.
4. Garantizar la disponibilidad y confiabilidad de la información.

6. Equipo de trabajo

- Persona 1: Líder del proyecto.
- Persona 2: Responsable de documentación.
- Persona 3: Responsable de cambios.
- Persona 4: Responsable de calidad y auditoría.

7. Gestión de configuración

Se utilizará GitHub para almacenar y organizar la documentación del proyecto. Cada integrante realizará modificaciones y las registrará mediante commits para mantener un historial de los cambios.

8. Ramas de trabajo

La rama principal será "main". También se creará una rama llamada "mejora-documentacion", donde se realizarán propuestas de mejora antes de integrarlas al proyecto principal.

9. Pull Request

Las modificaciones realizadas en la rama secundaria serán presentadas mediante un Pull Request para que otro integrante pueda revisarlas y aprobarlas antes de integrarlas a la rama principal.

10. Auditoría y trazabilidad

Se revisará el historial de GitHub para identificar quién realizó cada cambio, qué modificó, cuándo lo hizo y si fue revisado y aprobado.

11. Conclusión

Esta actividad nos permite comprender la importancia de la gestión de configuración en los proyectos de software. Mediante GitHub podemos trabajar en equipo, organizar la documentación, registrar modificaciones y mantener un historial que facilite la revisión y el seguimiento del proyecto.
